How detection works

Hyper Engine scores a mod folder against machine-readable engine definitions (plain TOML in the repository). It reads metadata files at the mod root and structural markers inside the folder:

EngineMetadataMods directoryOrder file
Psych Enginepack.json / mods.jsonmodsmodsList.txt
Codename Enginemetadata.json + main.xmlmodsmodOrder.txt
FPS+ (Psych Plus)meta.json with a unique uidmodsorder
Funkin’ Officialmanifest.jsonmods—

Detection is decisive (High confidence) only when one engine owns the mod’s metadata files. Otherwise the best-scoring candidate is shown with its evidence, and hfe run --engine id overrides.

Installation model

  • Engines are stored side-by-side by tag (engines/psych/1.0.4/…).
  • Downloads are cached, checksummed (SHA-256), and zip-slip guarded.
  • Everything is HTTPS-only; a broken release never overwrites an installed one.
  • Uninstall/cleanup asks for consent before removing files.

Command line — hfe

hfe init [--engine psych] [--yes]                 # scaffold a mod + remember the engine
hfe run [PATH] [--engine id] [--version tag]      # detect, fetch if needed, stage, launch
hfe add assets <path>                              # point at a local base-game copy
hfe update --check | --apply                        # self-update (verified, rollback on fail)
hfe list [--installed]                              # engines and installed versions
hfe doctor                                          # environment diagnostics
hfe bench PATH                                      # measured launch/load numbers (only real measurements)
hfe pkg install foo                                 # package registry (coming soon)
hfe engines list --remote                           # engines known to Hyper Engine

Flags common to prompts: --yes / --no-input make scripts non-interactive. Exit codes are documented in hfe --help.

Running a mod

hfe run "C:\Mods\MyPsychMod"          # detects Psych, installs matching engine, launches

Hyper Engine stages the mod into a fresh engine install (it never modifies a shared engine), then records the choice so the next launch is instant.

Headless / CI use

hfe run . --dry-run                     # plan without touching anything
hfe bench . --format json                # emit measured numbers

Updates & rollback

The CLI can update itself from the official update manifest. The previous binary is kept so a failed update rolls back automatically; nothing is ever replaced until the new artifact verifies.

Privacy by default

No telemetry. Engine lists come from the official GitHub APIs; a GitHub token you optionally provide is stored only in your OS keyring and sent only to GitHub. See Privacy.
